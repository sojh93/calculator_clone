# intent.md — 윈도우 계산기 클론코딩

> 문서 흐름: **intent.md** (왜 만드는가) → spec.md (무엇을 만드는가) → plan.md (어떻게 만드는가)

---

## 1. 배경

Windows 계산기는 누구나 써본 소프트웨어로, 입력 → 연산 → 결과 표시라는 단순해 보이는 흐름 안에
**상태 관리, 엣지 케이스 처리, 키보드 인터랙션, 부동소수점 정밀도** 같은 프런트엔드 개발의 핵심 주제가 모두 들어 있다.
요구 동작이 이미 "정답"으로 존재하므로, 클론코딩 대상으로 적합하다.

## 2. 해결하려는 문제

| 문제 | 설명 |
|---|---|
| 요구사항이 모호한 상태로 코드부터 짜는 습관 | 문서(의도 → 명세 → 계획)를 먼저 확정하고 그에 맞춰 구현하는 개발 흐름을 연습한다. |
| 계산기 상태 관리의 복잡성 | "5 + 3 × 2 =", "= 반복 입력", "연산자 교체", "에러 후 복구" 등 상태 전이가 많아 구조화 없이는 버그가 쌓인다. |
| 부동소수점 오차 | `0.1 + 0.2 = 0.30000000000000004` 문제를 그대로 노출하면 계산기로서 실격이다. |
| UI와 로직이 뒤섞인 코드 | 컴포넌트 안에 계산 로직이 섞이면 테스트와 확장이 어렵다. |

## 3. 목적

1. Windows 10/11 **표준(Standard) 계산기의 실제 동작**을 React로 재현한다.
2. **계산 엔진(순수 함수) / 상태 관리(reducer) / UI(컴포넌트)** 3계층을 분리하는 설계를 연습한다.
3. **문서 주도 개발(Document-Driven Development)** 흐름을 경험하고, 문서가 곧 구현 기준이자 테스트 기준이 되게 한다.
4. 단위 테스트로 검증 가능한 구조를 만든다.

## 3-1. 목적이 아닌 것 (Non-Goals)

- Windows 계산기와 픽셀 단위로 동일한 디자인 (비슷한 분위기면 충분)
- 공학용 / 프로그래머 / 그래핑 / 날짜 계산 / 단위 변환 모드 (1차 범위 밖, 확장 후보로만 기록)
- 서버·DB 연동, 로그인 등 백엔드 기능
- 모바일 네이티브 앱화

## 4. 대상 사용자

- **1차 사용자**: 이 프로젝트를 만드는 본인 (학습 목적)
- **2차 사용자**: 포트폴리오로 코드를 읽는 사람 → 구조가 읽기 쉬워야 한다.

## 5. 기대 결과

### 5-1. 산출물
- 브라우저에서 동작하는 **표준 모드 계산기** 웹 앱 (React)
- 마우스 클릭과 **키보드 입력** 모두 지원
- 계산 **기록(History)** 과 **메모리(MC/MR/M+/M−/MS)** 기능
- 계산 엔진에 대한 **단위 테스트**와 주요 시나리오 **컴포넌트 테스트**
- 본 문서 세트 (intent / spec / plan)

### 5-2. 성공 기준 (Definition of Success)

- [x] spec.md에 정의한 모든 기능 요구사항(FR)이 구현되어 있다.
- [x] spec.md의 시나리오 표(계산 예시)가 **테스트 케이스로 100% 통과**한다.
- [x] `0.1 + 0.2` 가 `0.3` 으로 표시된다.
- [x] 0으로 나누기, 음수 제곱근 등에서 앱이 깨지지 않고 오류 메시지 후 복구된다.
- [x] 계산 로직 코드가 React에 의존하지 않는다. (엔진 단독 테스트 가능)
- [x] 키보드만으로 모든 기본 연산이 가능하다.

### 5-3. 학습 성과 (개인 목표)
- `useReducer` 기반 상태 머신 설계
- 순수 함수 중심의 로직 분리와 테스트 작성
- 키보드 이벤트 / 접근성(aria) 처리
- 문서 → 구현 → 검증의 추적 가능한 개발 방식

## 6. 가정과 전제

- 기술 스택은 **React 18 + Vite + TypeScript**, 테스트는 **Vitest + React Testing Library** 로 한다. (변경 시 spec.md만 수정)
- 정밀 연산에는 `decimal.js` 를 사용한다.
- 지원 브라우저는 최신 Chrome / Edge / Firefox / Safari.
- 동작 기준은 **Windows 11 계산기 표준 모드**이며, 판단이 필요할 때 이를 우선한다.
